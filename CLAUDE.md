## Аккаунты и роли
- **Регистрация (с 06.11.2026):** сначала по номеру телефона (+998), под ней кнопка «через почту» и Google. **С 08.11.2026 коды при регистрации выключены** (решение владельца: номер и почта нужны для новостей и восстановления пароля) — аккаунт создаётся сразу, номер/почта не подтверждены (`verified_at` пустой); включить обратно: переменная `REGISTER_CODES=on` на Render (`registerCodes()` в `auth.js`, сайт видит `verify.register` в `/api/config`). Код остаётся в «Забыли пароль?». **Вход** тоже сначала по номеру (поле +998 и пароль), под ним «Войти через почту или логин»; «Войти как родитель» на лендинге сразу открывает почту/логин. Номер хранится как логин в колонке `email` (`998XXXXXXXXX`) и в `users.phone`; входить можно номером, почтой или логином. Коды — таблица `verify_codes` (6 цифр, хеш HMAC, 10 минут, 5 попыток), лимиты в `verify_sends`: повтор через 60 с, 5 кодов на номер/почту в день, 10 с одного IP в час, всего SMS не больше `SMS_HOURLY_LIMIT` (60) в час и `SMS_DAILY_LIMIT` (300) в день. «Забыли пароль?» → «Получить код» — новый пароль по коду из SMS или письма. Отправка — `notify.js`: SMS через **DevSMS** (devsms.uz, API v1, «universal OTP», свой шаблон не нужен; переменная `DEVSMS_API_KEY`, имя в SMS `DEVSMS_SERVICE_NAME`, по умолчанию «Nimi AI»), или **бесплатно с телефона владельца**: приложение «SMS Gateway for Android» (sms-gate.app, бесплатный облачный сервер) на Android-телефоне с SIM-картой, переменные `SMSGATE_LOGIN` и `SMSGATE_PASSWORD` (их показывает приложение в разделе Cloud Server; если задан `DEVSMS_API_KEY`, используется DevSMS), текст «Nimi AI: 123456 — tasdiqlash kodi / код подтверждения»; телефон должен быть включён и в интернете; почта через **Brevo** (`BREVO_API_KEY` + `MAIL_FROM` — адрес, подтверждённый в Brevo, `MAIL_FROM_NAME`). Пока ключа нет — этот способ просто выключен: без `DEVSMS_API_KEY` регистрация по телефону не показывается, без Brevo почта регистрируется без кода (как раньше). Render на бесплатном тарифе не даёт отправлять почту по SMTP, поэтому только HTTP-API.
- **Согласия:** при регистрации две галочки (тексты — `CONSENT_TEXTS` в `auth.js`, версия `CONSENT_VERSION`; сайт берёт их из `/api/config`): правила и конфиденциальность — обязательно, без неё регистрация не проходит; новости/реклама по SMS, почте и звонкам — по желанию, не отмечена заранее. Каждое согласие и отказ пишутся в таблицу `consents` (текст, язык, IP, браузер, время). Кто зарегистрировался раньше или через Google в приложении — один раз видит окно «Ещё один шаг». Отказаться от рассылки: «Настройки» → «Новости и акции». В админке вкладка **«Рассылка»** (`POST /api/admin/consents`): только согласившиеся, скачать телефоны/почты в CSV (для «Guruhli SMS» в DevSMS нужен одобренный рекламный шаблон). Рекламу и звонки — только этим людям. **SMS-рассылка из админки** (там же, блок «SMS-рассылка с вашего телефона», с 08.11.2026): текст пишет админ, сначала «Отправить пробное SMS» на свой номер, потом «Кому отправить» — Всем / С подпиской / На бесплатной неделе / Без подписки / Выбрать вручную (галочки); получатели — только согласившиеся с телефоном (согласие проверяется ещё раз перед каждой SMS). Отправка через телефон-шлюз SMSGate медленно: очередь `sms_outbox` в базе, 1 SMS каждые `SMS_BROADCAST_EVERY_SEC` (20) с, не больше `SMS_BROADCAST_DAILY` (100) в день, остаток на следующий день; одна рассылка за раз, «Остановить» отменяет неотправленные. - **Родитель** — только «Кабинет родителя»: доступ ребёнка, статистика, темы, домашка, отчёт ИИ, заявка на неделю/подписку, смена пароля ребёнку.
- **Админ** (логин `nimi-admin`, пароль у владельца) — только админ-панель. Две вкладки: **«Показатели»** (дашборд: ученики, подписки по тарифам, деньги, активность, графики за 30 дней, разделы, токены ИИ и кто больше всех тратит — `POST /api/admin/stats`, считаются только ученики) и **«Ученики и заявки»**: заявки, ученики, неделя/месяц, «Снять подписку» у одного ученика, «Снять подписки у всех, кроме…» (сначала показывает список, снимает только его после подтверждения — `POST /api/admin/revoke-except`), новый пароль, удаление. Снятие подписки = доступ заканчивается сейчас (`premium_until = now()`), тариф в истории остаётся. Новый админ-аккаунт создаётся только ключом: `POST /api/admin/create-admin {"login": "..."}` с `X-Admin-Key` (пароль придумает сайт; можно задать свой: `{"login": "...", "password": "..."}`, минимум 8 символов, буквы и цифры). Админы: `nimi-admin`, `nimi-admin1`, `nimi-admin2`, `nimi-admin3`.
- **Защита от подбора пароля (с 08.11.2026):** 5 неверных паролей к одному аккаунту за 15 минут (с любых адресов, вместе) → аккаунт закрыт на 15 минут, даже верный пароль не принимается (`MAX_FAILED_PER_ACCOUNT` в `auth.js`, счёт в памяти сервера). Плюс старый предел — 10 ошибок с одного IP. Причина: IP хакер может подделать (заголовок X-Forwarded-For), поэтому только по IP пароль можно было перебирать бесконечно.
- **Face ID для админов ВЫКЛЮЧЕН (с 11.11.2026, решение владельца):** в админку входят только по паролю (плюс защита от подбора пароля). Включить обратно: переменная `ADMIN_FACE_ID=on` на Render (`faceIdOn()` в `server.js`; сайт видит `faceId` в `/api/config`, карточка «Вход по Face ID» в админке показывается только при включённом). Сохранённые ключи админов не удалены. Ниже — как это работает, если включить.
- **Face ID для админов обязателен (с 08.11.2026, вечер; при `ADMIN_FACE_ID=on`):** одного пароля мало. Админ (`role = 'admin'` или почта из `ADMIN_EMAILS`) без ключа после пароля видит окно «Включите Face ID» (`twoFactor: 'passkey_setup'`, `askPasskey(true)` в `app.js`, маршруты `POST /api/auth/passkey/setup-options|setup-verify` — только пока у аккаунта нет ни одного ключа) и не попадает в админку, пока не добавит свой телефон. Уже открытые сессии админов без Face ID при следующем заходе тоже переводятся в это окно (`handleMe`), админ-API отвечает 401 `passkey_setup`. Каждый админ добавляет свой телефон в своём аккаунте; новое устройство — только из уже вошедшей сессии (карточка «Вход по Face ID»). Код в `server.js`: `mustUsePasskey`, `secondStep`. Сейчас выключено (см. выше).
- **Вход в админку по Face ID (с 08.11.2026, бесплатно)** — WebAuthn-ключи (passkeys, библиотека `@simplewebauthn/server` v13, нужен Node ≥ 20): Face ID на iPhone, отпечаток/лицо на Android, Windows Hello на компьютере. Включает сам админ: «Админка» → вкладка «Ученики и заявки» → внизу карточка «Вход по Face ID» → «Добавить это устройство» (можно несколько устройств, «Убрать» — удалить). Если у аккаунта есть хотя бы один ключ, вход = пароль (или Google) → окно «Подтвердите вход» → «Войти по Face ID»; до этого сессия «ждёт» (`sessions.pending_2fa`, `getUser` её не видит, `pendingUser` видит), ни один API не работает. Код: `passkeys.js` (проверка), таблица `passkeys` и `holdSession/releaseSession` в `auth.js`, маршруты `POST /api/auth/passkey/options|verify` и `/api/admin/passkeys|passkey-options|passkey-add|passkey-delete` в `server.js`, окно `askPasskey()` в `app.js`, карточка `faceIdBlock()` в `learn-ui.js`. **Потеряли телефон** — владелец пишет «сбрось Face ID для <логин>», Claude: `curl -s -X POST https://nimi-ai.onrender.com/api/admin/passkey-reset -H 'Content-Type: application/json' -H "X-Admin-Key: $ADMIN_API_KEY" -d '{"login":"nimi-admin"}'` — ключи удаляются, вход снова по паролю. Ключ привязан к адресу сайта: после перехода на nimi.uz ключи надо добавить заново (на старом адресе продолжат работать). **В Android-приложении (с версии 1.2, versionCode 3):** WebView не умеет passkeys, поэтому как со входом через Google: кнопка «Войти по Face ID» / «Добавить это устройство» → `POST /api/auth/passkey/app-ticket` (одноразовый билет на 5 минут, в памяти сервера: `login` — для сессии, ждущей Face ID; `enroll` — только для вошедшего админа) → `NimiAndroid.openPasskey('/app-passkey.html?mode=…&t=…')` открывает Chrome Custom Tab → страница берёт `app-options` и шлёт `app-verify` → сервер выдаёт тот же одноразовый код, что для Google (`APP_CODES` с `passkeyChecked`, поэтому `app-exchange` не просит Face ID снова) → `intent://auth?code=…` → приложение входит. В старом приложении (1.1) вместо этого надпись «нужна новая версия приложения». Вызовы проверки (challenge) хранятся 5 минут в памяти сервера.
- «Забыли пароль?»: родитель ставит новый в своём кабинете, или владелец сбрасывает в админке (кнопка «Новый пароль»). Письма на почту пока не отправляются.
- Страницы: первый экран для гостей — лендинг для родителей; `/privacy.html` — правила и конфиденциальность (ru/uz). `/proof.html` — открытый отчёт о проверке 30–31.10.2026 (100 диалогов «дай ответ» и 1 310 проверок функций); на него ведёт QR-код в презентациях, вход не нужен. - **Рейтинги (с 08.11.2026)** — `openLeaderboard(board, back, period)` в `learn-ui.js`; вкладки «Путь знаний · XP» и «Игры · монетки», переключатель «Эта неделя» (с понедельника, ташкентское время) / «Всё время». **Очки считает сервер, а не браузер** (таблица `leader_points`, по дням): после урока `path.js` шлёт `POST /api/leaderboard/add {board:'path', amount}`, после боя `quest.js` — `{board:'games'}`; сервер (`addLeaderPoints` в `auth.js`, правила `LEADER_RULES`) берёт за раз не больше 20 XP / 100 монет, не чаще раза в 30 с / 15 с и не больше 300 XP / 1000 монет в день.
